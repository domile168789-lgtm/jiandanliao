# 柬单聊全端交付设计

## 背景

当前仓库已经具备 `Web/H5`、`Android`、`iOS`、`admin-desktop`、`api`、`ws` 的多端骨架与部分联调能力，但此前在“保留哪些后台”“用户端围绕什么完成”“是否先统一视觉还是先做完整功能”这些问题上发生过反复切换，导致范围不稳定。

本次设计用于一次性锁定 `柬单聊` 的交付边界、功能清单、开发顺序和验收方式，作为后续唯一执行基线。

## 目标

- 将项目对外产品名称统一为 `柬单聊`
- 仅保留 `admin-desktop` 作为唯一管理后台
- 将 `Web/H5`、`Android`、`iOS` 三个用户端补齐到完整版功能范围
- 让用户端功能与后台能力形成真实联动闭环
- 按用户确认的 `方案 A` 执行：先完成全端功能，再统一全端视觉风格
- 完成后先打开用户端和管理后台给用户确认功能，再进行最终收口、部署与发布

## 非目标

本设计当前不包含以下内容：

- 恢复或继续维护 `admin-web`
- 立即修改技术层永久标识，例如包名、`bundle id`、仓库目录名、数据库表名
- 在功能尚未补齐前先做大规模视觉重构
- 扩展到当前仓库不存在的独立“用户 Windows 桌面端”

## 固定产品边界

### 管理后台

- 唯一后台为 `apps/admin-desktop`
- 后台视觉主基准为用户已确认的暗色总控台截图
- 后台必须承担对用户端的运营、审核、配置、统计和代理支撑能力

### 用户端

- 用户端固定为三端：
  - `Web/H5`
  - `Android`
  - `iOS`
- 三端功能范围保持一致，允许在交互呈现上按平台习惯做微调

### 共享后端

- `apps/api` 作为统一 HTTP 业务后端
- `apps/ws` 作为统一实时消息通道
- 后台与三端用户端必须共用同一套业务数据与权限结果

## 命名策略

本轮将项目对外展示名称统一改为 `柬单聊`，默认包含：

- 页面标题
- 登录页文案
- 下载页文案
- 后台标题
- 用户端应用显示名
- 面向用户和运营的展示文案

本轮默认不强制修改：

- 包名
- `bundle id`
- 仓库目录名
- `npm package name`
- 数据库表名

## 后台与用户端联动要求

以下联动必须构成闭环：

1. 用户封禁联动
   - 后台封禁后，用户端应出现明确受限提示
   - 登录受限与发言受限要区分反馈
2. 举报联动
   - 用户端可发起举报
   - 后台可查看、处理、流转状态
   - 用户端可在系统通知中看到处理反馈
3. 群管理联动
   - 后台对群、群主、成员相关管理变更后，用户端实时生效
4. 活动联动
   - 后台发布活动后，用户端发现页与活动中心可见
   - 活动提醒可进入系统通知会话
5. 公告联动
   - 后台发布公告后，用户端公告页和系统通知可见
6. 财务与代理联动
   - 钱包、收益、代理数据与后台统计口径一致

## 执行策略

### 总策略

用户已确认采用 `方案 A`：

- 先完成全端功能
- 后统一所有端视觉风格

### 开发顺序

#### 第一阶段：后台能力补齐

先完成唯一管理后台的正式功能与真实数据接入，覆盖：

- 仪表盘
- 用户管理
- 群组管理
- 群主管理
- 举报审核
- 财务报表
- 代理管理
- 活动管理
- 品牌与基础配置

#### 第二阶段：用户端功能补齐

先按功能完整性推进，不先追求最终视觉统一，固定顺序为：

1. 消息区
2. 联系人区
3. 我的区
4. 发现区
5. 安全与系统通知

#### 第三阶段：联动校正

对后台与用户端做联动闭环校验，重点检查：

- 封禁
- 举报
- 群管理
- 活动
- 公告
- 钱包/收益/代理

#### 第四阶段：统一视觉

最后统一以下内容到同一设计语言：

- 管理后台
- Web/H5 用户端
- Android 用户端
- iOS 用户端
- 全部对外品牌名称 `柬单聊`

## 并行开发组织方式

用户要求“每个端都安排一个子代理一起来开发”，后续实施阶段按以下组织方式执行：

- 后台端子代理：负责 `admin-desktop`
- Web/H5 子代理：负责 `apps/web`
- Android 子代理：负责 `apps/android`
- iOS 子代理：负责 `apps/ios`

并行开发的前提约束：

- 必须先由主代理锁定统一接口、命名、页面边界和验收口径
- 各子代理不得自行扩展需求或改变产品边界
- 所有端的联动字段、状态定义、接口契约由主代理统一收口
- 并行开发后必须经过一次主代理整合验收

## 验收方式

### 中间验收

在开发完成后，先不直接收尾部署，先给用户看：

1. 用户端预览
2. 管理后台预览

用户重点确认：

- 功能是否齐全
- 页面结构是否正确
- 联动是否成立
- 对外名称是否统一为 `柬单聊`

### 最终验收

#### 用户端

- 登录注册可用
- 单聊群聊可用
- 图片消息可用
- 已读回执可用
- 联系人和群管理可用
- 发现、活动、公告可用
- 钱包、收益、代理入口及数据可见
- 安全、黑名单、举报反馈可见

#### 管理后台

- 暗色后台风格保持为最终后台基准
- 用户、群、群主、举报、财务、代理、活动均可操作
- 配置修改后能反映到用户端

#### 品牌统一

- 对外展示名统一为 `柬单聊`

## 风险与控制

### 风险

- 多端并行开发导致接口和状态定义漂移
- 先做完整功能容易让视觉短期内不统一
- 后台页面已存在但后端能力未完全闭环，容易误判完成度

### 控制策略

- 先锁定统一功能清单与联动规则
- 主代理统一接口口径，子代理只在口径内开发
- 每个阶段结束后做一次整合性验收
- 在最终统一视觉前，不允许再次切换产品方向

## 成功标准

当以下条件全部满足时，认为本轮设计目标达成：

- `admin-desktop` 成为唯一正式后台
- 三个用户端均达到完整版功能范围
- 后台与用户端关键联动全部闭环
- 对外展示名称统一为 `柬单聊`
- 完成后可先向用户展示用户端和管理后台进行确认
