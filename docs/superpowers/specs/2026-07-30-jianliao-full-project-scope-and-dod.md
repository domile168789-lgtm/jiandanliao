# 柬聊项目全量范围清单 & 生产运营级 DoD（一次确认版）

> 本文档用于锁定“剩下的功能 = 全部要做什么”，并定义“做到生产运营级”的验收门槛。你确认这份清单后，我将以它作为唯一范围基线，按优先级一路开发到全部完成。

## 1. 生产运营级（DoD）定义

当且仅当以下条件全部满足，视为达到“生产运营级”：

### 1.1 功能验收（面向用户）

参考仓库内发布检查单 `docs/release-checklist.md`，必须满足：

- 注册、登录、刷新令牌通过
- 单聊：文本、图片、文件、语音、视频通过
- 群聊：创建、邀请、退群通过
- 系统/运营：公告、系统消息、活动中心可用
- 投诉/举报：用户可提交，后台可查询处理

### 1.2 功能验收（面向运营/后台）

- 后台封禁用户、公告发布、投诉查询、审计查询通过
- 后台对“用户可用”的配置项必须在用户端可见（例如主题、公告、活动）

### 1.3 稳定性与可运营

- 监控面板可见 API/WS/MySQL/Redis 指标（最小：存活、延迟、错误率、连接数）
- 可回滚/可恢复：可执行一次备份与恢复演练  
  - 备份脚本：`scripts/deploy/backup-phase1.sh`（已存在）  
  - 恢复脚本：`scripts/deploy/restore-phase1.sh`（已存在）
- 生产部署手册完整可用：`docs/deploy/rocky9-production-runbook.md`（已存在）
- CI/CD：至少具备自动化 `test/build` 门禁与可重复发布（当前缺）

## 2. 当前完成度快照（基于仓库现状）

> 这是“现在已经有什么”的事实清单，用于标注剩余缺口。

### 2.1 后端（apps/api, apps/ws）

已具备（可构建/可测试）：
- 认证：注册/密码登录/refresh-token（见 `docs/api-contracts/phase1-backend.md`）
- 会话：会话列表、创建私聊（DM）
- 消息：拉取消息、发送消息、回执（READ/DELIVERED）
- 文件：已有上传元数据接口与 file service（但仅明确 image/* 规则）
- WS：基于 Socket.IO 的 auth + conversation join，推送 message/receipt（契约文档已存在）
- 管理插件：admin-auth、auth plugin

存在明显缺口：
- “微信级”统一协议尚未落地到实际代码：SYSTEM 会话、全量事件、未读策略统一、断线重连与增量同步
- 语音/视频/文件：需要明确上传、转码、访问与多端播放策略（你已选择“服务端统一转码”）
- 群聊完整生命周期（创建/邀请/退群）需补齐
- 风控/限流/反刷：目前只有 risk.service 轮廓，缺端到端策略与落点
- 可观测性（metrics/trace/告警）缺

### 2.2 用户端 H5（apps/web）

现状：
- 登录/注册页可用（你刚做了马年主题登录页）
- 主壳 MainShell：会话列表加载存在，但 TabBar 仍在迭代中（刚修 tab 点击切换）

缺口（距离微信级很大）：
- URL 路由体系（messages/chat/contacts/discover/me/settings/login/register）未建立
- 聊天页、发送文本/图片/语音、消息列表分页、未读红点、系统消息会话未实现

### 2.3 Android（apps/android）

现状（按 README 描述 + 工程结构）：
- Phase1 联调骨架已存在：登录/会话/文本/图片/READ 回执/WS join

缺口：
- 四 Tab 微信 UI/交互
- 群聊、系统消息会话
- 语音录制与播放（及服务端转码链路）
- “生产级登录态保持/自动重连/错误恢复”需要补齐

### 2.4 iOS（apps/ios）

现状：
- SwiftUI 联调骨架：Login/Conversations/Chat + APIClient + WSClient + Models
- README 明确：双向文本/图片/READ 回执联调目标

缺口：
- 四 Tab 微信 UI/交互
- 群聊、系统消息会话
- 语音录制与播放（及服务端转码链路）
- 登录态保持、重连与一致性策略补齐

### 2.5 管理后台（apps/admin-web, apps/admin-desktop）

现状：
- admin-web：登录、用户、举报、审计、公告等最小页面存在（smoke test 通过）
- admin-desktop：更丰富页面框架（活动中心、品牌配置、财务报表、群/群主等），但不代表全部后端能力已实现

缺口：
- 后台能力与用户端联动未闭环（公告→系统会话、活动→发现/系统会话、品牌→三端同步）
- 权限/RBAC/审计策略需明确并落地（当前更多是“页面存在”）

### 2.6 部署与运维（infra）

现状：
- compose 能跑通：nginx + api + ws + mysql + redis + minio
- 健康检查与运维手册存在
- 备份与恢复脚本存在

缺口：
- CI/CD 自动化缺（仓库未见 workflows）
- 监控与告警缺（release-checklist 要求“监控面板可见指标”）
- 密钥管理与轮换流程需要固化（防止运营风险）

## 3. “全量功能清单”（开发范围基线）

下面按模块列出“必须完成”的全量范围。每条都包含验收口径（DoD）。

### A. 账号与登录（用户端三端 + 后端）

1. 手机号即账号（含区号），注册/登录/刷新 token
2. 登录态保持（H5 刷新、Android/iOS 重启）
3. 退出登录、踢下线（可选）

**验收：**
- 三端都可注册/登录/刷新令牌
- token 过期能回登录页/登录页

### B. 微信四 Tab（H5/Android/iOS）

1. 消息 Tab：会话列表 + 未读红点 + 搜索（可先本地过滤）
2. 通讯录 Tab：联系人列表 + 分组/索引 + 搜索 + 发起单聊
3. 发现 Tab：入口列表（占位即可，但需可配置落点）
4. 我的 Tab：个人信息 + 设置 + 退出登录

**验收：**
- 三端 Tab 行为一致（切换/返回/刷新/恢复）

### C. IM：单聊（微信级）

1. 聊天页：消息列表分页、实时追加、时间/气泡基础样式
2. 文本：发送/接收/失败重试（最小）
3. 图片：选择/上传/发送/展示
4. 语音：录音/上传/发送/播放（服务端统一转码）
5. 文件：上传/发送/下载（最小）
6. 视频：上传/发送/播放（可先最小播放）
7. 回执：DELIVERED/READ（至少 READ 必须闭环）
8. 未读：会话维度未读数、进入会话清零、列表红点实时同步

**验收：**
- 三端之间可互发文本/图片/语音/文件/视频并互相可见
- READ 回执在三端与后台日志可观测

### D. IM：群聊（微信级最小）

1. 创建群聊
2. 邀请成员
3. 退群
4. 群聊消息收发与未读策略同单聊

**验收：**
- 三端能创建群、邀请、退群；群消息与未读正确

### E. 系统消息（SYSTEM 会话）

1. SYSTEM 会话存在且参与排序/未读
2. 公告/活动/机器人提醒等可写入 SYSTEM 会话

**验收：**
- 后台发布公告后，用户端 SYSTEM 会话出现新消息并红点增加

### F. 运营与风控（后台 + 用户端联动）

1. 举报/投诉：用户端发起，后台处理闭环（OPEN→CLOSED 等）
2. 封禁：后台封禁用户，用户端即时受限（禁止发言/禁止登录等按策略）
3. 审计：后台关键操作记录（已存在表与页面，需补完整链路）
4. 风控限流：登录/发消息/上传文件基本限流与防刷

**验收：**
- 后台执行封禁后，用户端行为立刻受影响且有明确提示
- 举报在后台可见且状态可变更

### G. 品牌与多端主题（后台→用户端）

1. Branding 配置（pc/mobile/h5/ios/android）统一
2. 节日主题优先级（holidayThemeAssetUrl）
3. 三端启动时拉取品牌并生效（登录页/首页可见）

**验收：**
- 后台改主题 → 三端刷新后都能看到主题变更

### H. 发现/活动中心（最小可运营）

1. 后台创建活动（activity campaigns）
2. 用户端发现页入口可跳转活动详情（可先 H5 页/占位）
3. 活动提醒可进入 SYSTEM 会话

**验收：**
- 后台发布活动后，用户端至少能看到入口与系统提醒

### I. 部署、监控、备份恢复（生产底座）

1. CI：自动 test/build 门禁（至少 pnpm workspace）
2. CD：可重复发布（镜像/compose 更新策略）
3. 监控：API/WS/MySQL/Redis 指标面板可见
4. 备份：定时备份 + 每月至少一次恢复演练

**验收：**
- release-checklist 的监控与备份/恢复项可完成

## 4. 优先级（建议执行顺序）

> 你要求“全量都做”，但落地必须有优先级，否则不可控。我建议按 P0→P1→P2 推进。

- **P0（先达成可用闭环）**：A + B(基础) + C(文本/图片/READ/未读) + I(最小)
- **P1（补齐微信级媒体与群聊）**：C(语音/文件/视频) + D + E + F(封禁/举报闭环)
- **P2（运营深化与体验对齐）**：G + H + I(监控面板完善/恢复演练制度化) + 微信细节（搜索/骨架屏/动效/长按等）
