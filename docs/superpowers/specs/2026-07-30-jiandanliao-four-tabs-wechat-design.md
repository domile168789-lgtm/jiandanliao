# 柬单聊四个 Tab 微信化改版设计

## 目标

- 把 Web/H5 用户端的 `消息`、`通讯录`、`发现`、`我的` 四个 Tab 调整为更接近微信的信息架构与交互层级。
- 优先复用柬单聊现有真实能力，不做纯视觉壳层。
- 已完成的 `消息 -> + -> 发起群聊` 直接并入本轮整体设计。

## 设计原则

- 像微信的交互结构，不直接复制微信品牌素材。
- 真实能力优先：已有的会话、钱包、收益、代理、资料、安全能力优先接真实页面。
- 骨架页次之：朋友圈、看一看、搜一搜、卡包、表情、公众号等入口先接统一骨架页，保证可点、可进、结构完整。
- 一轮只完成 Web/H5，Android/iOS 后续按同一结构对齐。

## 总体结构

### 消息

- 顶部保留 `消息` 标题与微信式 `+` 菜单。
- `+` 菜单本轮包含：
  - 发起群聊（已实现，继续保留）
  - 添加朋友
  - 扫一扫
  - 收付款
- 会话列表改为更接近微信的列表行样式，减少卡片感。
- 登录失效提示改为更轻的顶部状态提示。

### 通讯录

- 顶部搜索框。
- 固定服务入口：
  - 新的朋友
  - 群聊
  - 标签
  - 公众号
- 下方展示联系人列表。
- 联系人仍支持发起单聊。
- `群聊` 入口跳转到群聊列表或群会话筛选页。

### 发现

- 固定入口分两层：
  - 第一层：朋友圈、扫一扫、看一看、搜一搜
  - 第二层：系统通知、钱包、收益、代理中心
- 活动中心保留，但降到微信式服务列表后面。
- 每个入口采用微信式列表行，不再使用大卡片宫格。

### 我的

- 顶部使用微信式个人卡片：
  - 头像占位
  - 昵称
  - 手机号/柬单聊号
- 中部服务入口：
  - 服务
  - 收藏
  - 朋友圈
  - 卡包
  - 表情
- 底部系统入口：
  - 个人资料
  - 安全中心
  - 设置
- 钱包、收益、代理等现有能力统一并入“服务”区。

## 入口映射

### 消息页 `+` 菜单

- 发起群聊 -> 真实建群链路
- 添加朋友 -> 跳转 `新的朋友` 页面
- 扫一扫 -> 跳转 `扫一扫` 骨架页
- 收付款 -> 跳转 `钱包/收付款` 骨架页

### 通讯录

- 新的朋友 -> 新页面，展示“按手机号添加朋友”的骨架与最近请求占位
- 群聊 -> 新页面，列出当前群会话
- 标签 -> 新页面，占位展示标签分组
- 公众号 -> 新页面，占位展示服务号/公告型账号

### 发现

- 朋友圈 -> 新页面，占位展示朋友圈流
- 扫一扫 -> 复用统一扫描骨架页
- 看一看 -> 新页面，占位展示推荐内容流
- 搜一搜 -> 新页面，占位展示搜索入口
- 系统通知 -> 现有真实页面
- 钱包 -> 现有真实页面
- 收益 -> 现有真实页面
- 代理中心 -> 现有真实页面

### 我的

- 服务 -> 新页面，聚合钱包、收益、代理等入口
- 收藏 -> 新页面，占位
- 朋友圈 -> 复用朋友圈骨架页
- 卡包 -> 新页面，占位
- 表情 -> 新页面，占位
- 个人资料 -> 现有真实页面
- 安全中心 -> 现有真实页面
- 设置 -> 现有真实页面

## 页面策略

- 现有真实页面直接复用：
  - `/h5/system-notice`
  - `/h5/wallet`
  - `/h5/earnings`
  - `/h5/agent`
  - `/h5/profile`
  - `/h5/security`
  - `/h5/settings`
- 本轮新增骨架页：
  - 新的朋友
  - 群聊
  - 标签
  - 公众号
  - 朋友圈
  - 扫一扫
  - 看一看
  - 搜一搜
  - 服务
  - 收藏
  - 卡包
  - 表情

## 视觉策略

- 四个 Tab 的首页统一采用微信式列表结构：
  - 白底/浅灰底
  - 行分隔
  - 轻图标占位
  - 右箭头
- 减少当前的卡片宫格和大面积说明文案。
- 空态统一变轻，不再使用大面积工程说明。

## 风险与边界

- 朋友圈、扫一扫、公众号、卡包、表情等本轮只做入口与骨架页，不承诺完整业务能力。
- 通讯录中的“新的朋友”本轮优先提供按手机号添加的入口结构，不做完整好友关系闭环。
- 本轮聚焦 Web/H5，不同时扩展 Android/iOS。
