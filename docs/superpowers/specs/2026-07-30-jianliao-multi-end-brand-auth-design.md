# 柬聊多端品牌登录页与后台品牌配置 Design

## 背景

当前用户端认证入口已经分化出多个端：

- `H5`
- `Android`
- `iOS`
- `PC 网页端`
- `Windows 桌面端`

现状问题有三类：

1. 用户端登录/注册首屏样式不统一，且之前做的 H5 简版注册页已经不符合最新要求。
2. 品牌内容目前不是后台可配置能力，无法由管理后台统一维护项目名称、LOGO 与底部主题位。
3. 管理后台的最终交付方式已经明确为 `Windows exe 安装包`，并且后台整体视觉要以用户最新上传的暗色仪表盘设计图为准，不再要求同时维护 Web 管理后台作为主要交付物。

本次目标不是只改某一个端，而是交付一套“同品牌、不同布局”的多端用户认证首屏，并为 Windows 管理后台增加对应品牌配置能力与桌面端视觉重构。

## 目标

本次设计目标如下：

1. 所有用户端默认进入`登录页`，不再默认进入注册页。
2. 登录页结构按最新线框重做，废弃之前已实现的简版 H5 认证页。
3. 统一品牌元素，但允许移动端与 PC 端使用不同布局。
4. 后台新增品牌配置能力，且按两组配置维护：
   - `移动端配置`：`H5 / Android / iOS`
   - `PC 端配置`：`PC 网页端 / Windows 桌面端`
5. 后台配置项仅包含 3 项：
   - `项目名称`
   - `项目 LOGO`
   - `底部背景 / 主题位`
6. 管理后台最终仅交付 `Windows exe` 安装包。
7. 管理后台整体视觉按用户提供的暗色仪表盘设计图进行重构。

## 不在本次范围

为保证本轮能快速落地并完成演示，下列内容不纳入本次实现：

- 完整的多语言系统，仅保留`全球语言切换`入口位
- 完整的忘记密码流程，仅保留`忘记密码`入口位
- 每个端单独一套品牌配置
- 复杂主题管理系统、皮肤市场或多套主题切换
- 改造用户登录后的主业务页面
- 为管理员额外交付 Web 版后台成品

## 方案选择

### 方案 A：全端共用一套品牌配置

优点：

- 后台最简单
- 实现成本最低

缺点：

- 不满足“移动端与 PC 端分开配置”的要求

### 方案 B：移动端一套、PC 端一套

优点：

- 满足用户确认的配置分组要求
- 后台复杂度仍然可控
- 能兼顾移动端与 PC 端不同视觉表达

缺点：

- 需要一层端到配置组映射

### 方案 C：每个端单独一套

优点：

- 灵活度最高

缺点：

- 后台配置复杂度明显上升
- 后续维护成本高

### 结论

采用`方案 B`：

- `移动端配置`：供 `H5 / Android / iOS` 使用
- `PC 端配置`：供 `PC 网页端 / Windows 桌面端` 使用

## 用户端设计

## 通用品牌元素

所有用户端登录页都必须统一展示以下品牌要素：

- `项目名称`
- `项目 LOGO`
- `底部背景 / 主题位`

所有用户端默认页统一为`登录页`，并统一包含以下交互元素：

- 账号输入
- 密码输入
- 密码显隐切换
- `登录`主按钮
- `记住密码`
- `忘记密码`
- `注册账号`
- `全球语言切换`入口

其中：

- `忘记密码` 本次只做入口位
- `全球语言切换` 本次只做入口位
- `注册账号` 为注册页入口，不再作为默认首屏

## 移动端布局

适用端：

- `H5`
- `Android`
- `iOS`

布局规则：

1. 使用单列卡片式结构。
2. 顶部展示品牌区：
   - `项目 LOGO`
   - `项目名称`
   - 可保留“网页端入口”或移动端副标题，但不得喧宾夺主。
3. 中部为表单区：
   - 账号行
   - 密码行
   - 登录按钮
   - 记住密码 / 忘记密码
   - 注册账号
4. 底部单独展示`底部背景 / 主题位`。
5. `全球语言切换`位于页面底部，作为辅助入口。

移动端视觉重点：

- 品牌信息在顶部聚焦
- 表单操作路径短
- 底部主题位独立成块

## PC 端布局

适用端：

- `PC 网页端`
- `Windows 桌面端`

布局规则：

1. 使用双栏结构。
2. 一侧为品牌展示区：
   - `项目 LOGO`
   - `项目名称`
   - `底部背景 / 主题位`
   - 可容纳欢迎语或品牌说明
3. 另一侧为登录卡片：
   - 账号
   - 密码
   - 密码显隐
   - 登录
   - 记住密码 / 忘记密码
   - 注册账号
   - 全球语言切换
4. 登录卡片应保持聚焦，不与品牌展示区抢主次。

PC 端视觉重点：

- 品牌展示更完整
- 表单区更集中
- 允许较大横向空间来承载主题位

## 后台设计

## 页面位置

管理员后台的最终交付物调整为 `Windows 桌面端`。本次新增的品牌配置能力应集成到 Windows 管理后台中，而不是以 Web 端后台作为主要交付界面。

后台当前没有“品牌设置”或“系统配置”页面，因此本次新增一个独立页面，建议命名为：

- `品牌配置`

该页面不应塞进公告创建页或用户页，以避免语义混乱。它应作为 Windows 管理后台左侧导航中的独立入口，与仪表盘、用户、举报、审计等模块并列。

## 后台视觉风格

Windows 管理后台整体视觉以用户提供的设计图为准，采用暗色仪表盘风格：

- 顶部信息条
- 左侧图标导航
- 首页指标卡片
- 中部统计图/平台分布图
- 用户列表表格
- 底部活动日志区

本次品牌配置页需要接入这一套视觉体系，不能继续沿用当前简化版表单后台样式。

## 配置分组

后台页面分为两组：

### 移动端配置

作用范围：

- `H5`
- `Android`
- `iOS`

字段：

- `项目名称`
- `项目 LOGO`
- `底部背景 / 主题位`

### PC 端配置

作用范围：

- `PC 网页端`
- `Windows 桌面端`

字段：

- `项目名称`
- `项目 LOGO`
- `底部背景 / 主题位`

## 字段语义

### 项目名称

展示在登录页品牌标题区域，用于表达当前项目/站点名称。

### 项目 LOGO

展示在登录页顶部或品牌区。后台需要支持替换，用户端不应写死固定图。

### 底部背景 / 主题位

用于登录页底部主题区域展示，可以是背景图、品牌主视觉图或主题位素材。该区域是本次用户指定必须支持后台自定义的视觉位。

## 数据模型

推荐引入一份品牌配置实体，按 `platformGroup` 存储：

- `mobile`
- `pc`

建议字段：

- `platformGroup`
- `projectName`
- `logoUrl`
- `themeAssetUrl`
- `updatedAt`
- `updatedBy`

说明：

- 本次只维护两条配置记录：`mobile` 与 `pc`
- 不扩成五端独立配置

## 接口设计

## 后台管理接口

后台需要具备：

- 读取品牌配置
- 更新品牌配置

建议接口语义：

- `GET /api/admin/branding`
- `PUT /api/admin/branding/:platformGroup`

其中 `platformGroup` 取值：

- `mobile`
- `pc`

后台读写权限建议与其他管理写操作一致，仅允许有写权限角色更新。

## 用户公开读取接口

用户端启动时需要能读取对应品牌配置。

建议新增公开接口：

- `GET /api/public/branding?group=mobile`
- `GET /api/public/branding?group=pc`

返回字段只包含前端展示必需信息，不暴露后台编辑信息。

返回建议包含：

- `projectName`
- `logoUrl`
- `themeAssetUrl`

## 端与配置映射

映射规则固定如下：

- `H5` -> `mobile`
- `Android` -> `mobile`
- `iOS` -> `mobile`
- `PC 网页端` -> `pc`
- `Windows 桌面端` -> `pc`

该映射规则由各端客户端在启动认证页时使用，不允许在当前版本中由用户手动切换端配置组。

## 交互设计

## 登录页

默认进入`登录页`，包含：

- 账号输入
- 密码输入
- 密码显隐按钮
- 登录主按钮
- 记住密码
- 忘记密码入口
- 注册账号入口
- 全球语言切换入口

## 注册页

注册页保留，但不再作为默认页。注册页样式需与登录页同品牌体系一致。

注册页至少需要与登录页保持以下一致：

- 顶部品牌区
- 品牌名称与 LOGO
- 底部主题位
- 语言切换入口

## 错误处理

### 后台配置为空

如果某组品牌配置为空，客户端应有兜底展示：

- 项目名称：使用默认名称
- LOGO：使用本地默认占位
- 主题位：使用默认背景块

### 配置资源失效

如果 `logoUrl` 或 `themeAssetUrl` 无法加载：

- 页面应继续可用
- 不得阻塞登录交互
- 应自动退回默认占位资源

### 用户端拉取配置失败

拉取品牌配置失败时：

- 记录错误
- 使用本地默认品牌兜底
- 认证页仍须可进入

## 测试与验收

## 后台验收

后台应满足：

1. Windows 管理后台首页视觉符合用户提供的设计方向
2. 能查看当前`移动端配置`
3. 能查看当前`PC 端配置`
4. 能分别修改两组配置
5. 修改后可立即被用户端读取
6. 能产出可安装的 Windows `exe` 包

## 用户端验收

### 移动端

- `H5 / Android / iOS` 默认进入登录页
- 均展示移动端品牌配置
- 项目名称、LOGO、底部主题位能跟随后台变更
- 页面结构符合线框要求，不再使用旧 H5 简版注册页

### PC 端

- `PC 网页端 / Windows 桌面端` 默认进入登录页
- 均展示 PC 端品牌配置
- 项目名称、LOGO、底部主题位能跟随后台变更
- 页面采用双栏或等价的 PC 端布局，不强求与移动端同版式

## 演示验收

完成后演示至少应覆盖：

1. Windows 管理后台首页按设计图完成视觉重构
2. 后台修改移动端品牌配置
3. 移动端登录页展示变化
4. 后台修改 PC 端品牌配置
5. PC 端登录页展示变化
6. 默认登录页正确显示
7. 注册页入口仍可进入，但不再是默认首屏
8. 能生成 Windows `exe` 安装包并打开演示

## 风险与注意事项

1. 多端 UI 技术栈不同，必须统一品牌字段语义，但不要强行复用同一套布局代码。
2. 品牌配置必须是弱依赖，配置接口失败不能阻塞登录。
3. 旧 H5 简版认证页需要整体替换，避免新旧页面并存造成体验混乱。
4. Windows 管理后台视觉改动范围会明显大于品牌配置页本身，必须先以用户提供的设计图统一首页框架，再把品牌配置入口嵌入其中。
5. 交付物包含 Windows `exe` 打包链路，因此需要补齐 Electron Windows 打包配置，而不仅是前端页面开发。

## 结论

本次采用“同品牌，不同布局；移动端一套、PC 端一套”的多端品牌登录页方案。

实施后将得到：

- 一套集成在 Windows 管理后台中的品牌配置入口
- 两组可维护的品牌配置
- 五个用户端统一进入登录页
- 移动端与 PC 端分别使用适合自身的布局
- 可通过后台修改`项目名称`、`项目 LOGO`、`底部背景 / 主题位`
- 一个符合设计图方向、可打包为 Windows `exe` 的管理员后台
