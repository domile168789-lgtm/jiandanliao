# 柬聊三端未登录默认注册设计

日期：2026-07-30  
状态：已确认，待进入实施计划

## 背景

当前柬聊用户端覆盖 Android、iOS 与 Web 三个入口，但未登录时的认证体验并不统一：

- Android 现为单页双按钮，默认视觉上更接近登录/注册并列操作
- iOS 现有 `LoginView`，但默认状态是登录
- Web 用户端目前仍是静态消息壳，没有真正的认证入口

为了统一演示口径，并符合“新增用户首次接触产品时优先走注册”的目标，本次调整统一为：

- 未登录时，每次进入都默认展示注册态
- 仍然保留切换到登录态的能力
- 已登录用户不受影响，仍直接进入会话/主界面

## 目标

本次设计只解决认证入口默认态，不扩展到验证码、onboarding、风控或完整 Web 聊天实现。

目标如下：

- Android 未登录进入时默认显示注册态
- iOS 未登录进入时默认显示注册态
- Web 未登录进入时默认显示注册态
- 三端都允许用户切换到登录态
- 退出登录后再次进入，仍默认注册
- 已登录用户继续直接进入已有主界面

## 不在本次范围

- 不做首次进入记忆
- 不做 onboarding 或欢迎引导
- 不做短信验证码注册
- 不新增后台配置项
- 不顺带改造完整 Web 用户聊天页面
- 不把当前线上用户鉴权 `401` 运行态问题并入这份设计

## 方案选择

本次采用统一方案：

- 三端都使用单一认证入口
- 默认模式为“注册”
- 页面内提供“切换到登录”的明确入口
- 登录与注册继续共用现有后端认证接口

采用这个方案的原因：

- 演示口径一致
- 改动可控
- 老用户仍可直接切换到登录，不会被阻断
- 不需要新增额外路由或复杂状态记忆

## Android 设计

涉及文件：

- `apps/android/app/src/main/java/com/jianliao/android/ui/screens/LoginScreen.kt`
- `apps/android/app/src/main/java/com/jianliao/android/ui/JianliaoApp.kt`
- `apps/android/app/src/main/java/com/jianliao/android/ui/vm/AuthViewModel.kt`（仅在需要时补充 UI 状态支持）

当前 Android 认证页是单页双按钮模式。调整后改为“单页模式切换”：

- 页面增加本地认证模式状态：`REGISTER` / `LOGIN`
- 默认进入 `REGISTER`
- 注册态展示：
  - 手机号
  - 密码
  - 昵称
  - 主按钮：`注册并进入`
  - 次级操作：`已有账号？去登录`
- 登录态展示：
  - 手机号
  - 密码
  - 主按钮：`密码登录`
  - 次级操作：`新用户？去注册`
- 页面标题文案改为更中性的认证文案，例如 `柬聊 - 欢迎使用`

行为要求：

- 未登录进入 `Routes.LOGIN` 时，每次都从注册态开始
- 登录成功或注册成功后，沿用现有 `onLoginSuccess -> Sessions` 导航
- 退出登录后再次回到 `Routes.LOGIN`，仍默认注册态

实现上优先保持模式状态为 `LoginScreen` 内部本地 UI 状态，不写入全局存储。

## iOS 设计

涉及文件：

- `apps/ios/JianliaoIOS/Features/Login/LoginView.swift`
- `apps/ios/JianliaoIOS/App/RootView.swift`

iOS 已有 `isRegister` 结构，因此改动最小：

- 将 `isRegister` 默认值从 `false` 改为 `true`
- 保留现有单页认证结构
- 将切换文案改为双向文案：
  - 注册态：`已有账号？切换到登录`
  - 登录态：`新用户？切换到注册`
- 注册态继续显示昵称字段
- 登录态隐藏昵称字段

行为要求：

- `RootView` 未登录时仍进入 `LoginView`
- 每次 `LoginView` 首次显示时默认进入注册态
- 已登录用户仍进入 `ConversationsView`
- 退出登录后重新进入认证页时，继续默认注册

## Web 设计

涉及文件：

- `apps/web/src/App.tsx`
- `apps/web/src/components/AuthPage.tsx`
- `apps/web/src/components/MainShell.tsx`

当前 Web 用户端还没有真实认证入口，因此需要补一个最小认证页。

本次只做最小可演示用户入口，不做完整聊天实现。Web 结构调整为：

- `App.tsx` 负责根据本地登录态显示：
  - 未登录：认证页
  - 已登录：现有主界面壳
- 新认证页默认处于注册态
- 提供切换到登录态的入口
- 页面字段与移动端保持一致：
  - 手机号
  - 密码
  - 昵称（仅注册态显示）

Web 本次采用固定落地深度：

1. 演示级前端态切换
   - 只做未登录默认注册的界面与本地登录态切换
   - 不依赖当前线上真实认证接口
   - 通过组件内或应用级轻量状态切换未登录/已登录展示
   - 不把本次改动扩展为完整 Web 聊天接入

Web 端本次实现必须满足以下 UI 行为：

- 未登录进入默认注册
- 可切换到登录
- 已登录进入主界面壳
- 退出后再次进入仍默认注册

## 状态与数据流

三端统一遵循以下认证入口规则：

1. 先判断是否已登录
2. 已登录：
   - Android 进入 `Sessions`
   - iOS 进入 `ConversationsView`
   - Web 进入主界面壳
3. 未登录：
   - 进入认证页
   - 默认选中注册态
4. 用户可手动切换到登录态
5. 登录或注册成功后进入主界面
6. 退出登录后，认证页重置回默认注册态

关键点：

- “默认注册”是未登录入口规则，不是持久化偏好
- 不记录“上次停留在登录还是注册”
- 不从 URL、LocalStorage、Keychain、SharedPreferences 读取认证页模式

## 文案要求

三端文案应尽量统一，不再使用含糊的“登录/注册”混合标题。建议：

- 页面标题：`欢迎使用柬聊`
- 注册主按钮：`注册并进入`
- 登录主按钮：`密码登录`
- 注册态切换文案：`已有账号？去登录`
- 登录态切换文案：`新用户？去注册`

如果受平台组件限制，允许轻微差异，但语义必须保持一致。

## 异常处理

本次不新增后端错误类型，只要求三端沿用现有错误显示机制：

- 注册失败时保留当前注册态并显示错误
- 登录失败时保留当前登录态并显示错误
- 切换模式时清理仅属于另一模式的错误文案或无效字段
- 退出登录后进入认证页时，初始状态不应残留上次错误信息

## 测试与验收

### Android

- 未登录启动时默认显示注册态
- 可切换到登录态
- 注册态显示昵称字段，登录态不显示
- 退出登录后再次进入仍默认注册

### iOS

- 未登录启动时默认显示注册态
- 可切换到登录态
- 注册态显示昵称字段，登录态不显示
- 退出登录后再次进入仍默认注册

### Web

- 未登录进入时默认显示注册态
- 可切换到登录态
- 已登录后可进入现有主界面壳
- 退出登录后再次进入仍默认注册

### 一致性验收

- 三端未登录默认态一致
- 三端都保留登录入口
- 已登录跳转行为不被破坏

## 实施顺序建议

1. 先修复线上用户鉴权 `401` 运行态问题，确保真实认证链可用
2. 再完成 Android 与 iOS 默认注册态改造
3. 最后补 Web 最小认证页与默认注册态
4. 统一做一次三端演示回归

## 风险与注意点

- Web 用户端当前认证基础最弱，实施时要避免把范围扩成“完整 Web IM”
- Android 当前是双按钮页，切成模式页时要注意不影响已有 ViewModel 成功回调
- iOS 改动虽小，但要确认切换文案和默认态不会影响 `restoreIfPossible()`
- 如果线上真实认证链仍未修复，Web 可能需要先走演示级本地态方案

## 结论

本次设计采用统一的“未登录时每次都默认注册，但保留切换到登录”策略，覆盖 Android、iOS、Web 三端。

该方案能以最小改动统一新增用户演示路径，同时保留老用户登录入口，不引入持久化偏好、不扩大功能范围，并与当前柬聊阶段 1 的多端联调目标保持一致。
