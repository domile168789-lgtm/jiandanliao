# 柬聊 H5 与下载页公网入口设计

日期：2026-07-30  
状态：已确认，待进入实施计划

## 背景

当前公网入口 `http://45.202.0.14/` 仍用于管理后台联调。用户侧入口还没有清晰的公网路径分工：

- 用户 H5 尚未有固定公网地址
- Android / iOS 下载入口尚未独立成页
- iOS 当前没有可分发签名证书，因此暂不具备直接下载安装条件

为了让演示和临时分发路径清晰可用，本次新增两条公网二级路径：

- `http://45.202.0.14/h5`：用户 H5 入口
- `http://45.202.0.14/app`：Android / iOS 用户端下载页

## 目标

本次设计目标如下：

- 为用户 H5 提供稳定公网入口 `/h5`
- 为移动端下载提供稳定公网入口 `/app`
- 保持根路径 `/` 继续服务现有管理后台
- Android 在 `/app` 提供真实下载入口
- iOS 在 `/app` 仅展示下载说明，后续证书就绪后再替换为真实安装入口
- 页面结构简洁、可直接用于当前阶段演示

## 不在本次范围

- 不改根路径 `/` 的现有后台用途
- 不引入正式官网或品牌站
- 不接入 App Store / TestFlight / 企业签名安装
- 不实现 iOS 真实下载安装
- 不顺带把 Web 用户端扩展成完整聊天产品站
- 不把当前线上用户鉴权 `401` 问题并入本次入口设计

## 入口分工

### `/`

- 保持现状
- 继续作为后台联调与管理入口
- 本次不改动其路由行为，避免影响已打通的后台链路

### `/h5`

- 固定映射到用户 H5 前端
- 打开后进入用户网页端入口页
- 未登录状态下，默认展示此前已确认的“注册态优先”认证页

### `/app`

- 固定映射到独立下载页
- 该页不承担 H5 聊天逻辑，只负责下载与安装说明
- Android 提供真实下载按钮
- iOS 仅展示说明文案

## 方案选择

本次采用“同一 Nginx 网关下按路径分流”的方案：

- `/` -> 后台
- `/h5` -> 用户 H5
- `/app` -> 下载页

采用该方案的原因：

- 不需要新增域名
- 与当前服务器 IP 临时使用方式一致
- 便于后续在证书、域名准备完成前持续迭代
- 风险低，不影响已联通的后台入口

不采用“全部挂根路径由单前端再分路由”的原因：

- 当前根路径已经承担后台用途
- 混合后台与用户端会增加入口冲突和部署复杂度

## `/h5` 页面设计

### 功能定位

`/h5` 是用户网页端入口，不是下载页，也不是后台入口。

本次 `/h5` 页面应做到：

- 可从公网 IP 直接访问
- 明确属于用户侧
- 未登录默认进入注册态
- 保留切换到登录态的入口
- 登录后进入现有用户 H5 主界面壳

### 页面结构

`/h5` 本次不做复杂官网布局，保持轻量入口即可：

1. 顶部标题区
   - 标题：`欢迎使用柬聊`
   - 副文案：`网页端入口`
2. 认证区
   - 默认注册态
   - 可切换到登录态
3. 登录后主界面壳
   - 继续使用当前 H5 主界面结构或最小主界面壳

### 行为要求

- 未登录打开 `/h5`，默认显示注册态
- 用户可切换到登录态
- 已登录进入用户主界面
- 退出登录后重新进入 `/h5`，仍默认注册态

## `/app` 页面设计

### 功能定位

`/app` 只承担下载与安装说明，不承担用户聊天功能。

页面目标是：

- 让演示对象清楚区分 Android 与 iOS 下载状态
- 让 Android 用户能直接下载安装
- 让 iOS 用户明确知道当前尚未开放安装

### 页面结构

下载页建议保持简洁，包含以下区块：

1. 顶部标题区
   - 标题：`柬聊下载`
   - 副文案：`请选择你的设备`
2. Android 下载区
   - 平台标题：`Android`
   - 状态说明：`可下载安装`
   - 主按钮：`下载安装 Android 版`
   - 辅助信息：
     - 构建时间或版本号
     - 若存在风险提示，可补充“如浏览器提示风险，请按设备提示继续安装”
3. iOS 说明区
   - 平台标题：`iPhone / iPad`
   - 状态说明：`安装通道准备中`
   - 主文案：`当前正在申请签名证书，证书就绪后将开放下载安装`
   - 不提供安装按钮
4. 底部说明区
   - 服务器 IP 临时访问说明
   - 如有需要可附加联系管理员提示

### Android 下载要求

`/app` 中 Android 下载按钮需要指向一个真实可访问的 APK 地址。

本次实施中允许两种具体落地方式，但实现结果必须统一呈现为一个直接下载按钮：

1. 将 APK 放到当前 Nginx 可访问静态目录
2. 将 APK 放到已有对象存储或已开放的静态资源路径，再由 `/app` 页面引用

无论选择哪一种，用户点击按钮后都应直接进入下载行为，而不是跳到说明页。

### iOS 要求

本次 iOS 固定要求如下：

- 不提供 TestFlight 链接
- 不提供 App Store 链接
- 不提供企业签名或 OTA 安装入口
- 仅展示“签名证书申请中，后续开放下载安装”的说明

后续证书准备完成后，再单独修改 `/app` 的 iOS 区块。

## 部署与路由设计

涉及现有网关文件：

- `infra/nginx/default.conf`

本次路由分流应调整为：

- `/api/` 继续转给 API
- `/socket.io/` 继续转给 WS
- `/uploads/` 继续转给 MinIO
- `/` 继续转给后台
- 新增 `/h5`
- 新增 `/app`

推荐实现方式：

- 将用户 H5 构建产物与下载页构建产物独立放置
- `nginx` 为 `/h5` 和 `/app` 增加单独 `location`
- 后台根路径保持不变

这样做的好处是：

- 路由职责明确
- 用户侧和后台侧互不影响
- 后续替换 `/app` 中 iOS 逻辑不会影响 `/h5`

## 前端工程边界

为了避免范围失控，本次建议工程拆分遵循：

- `apps/web` 承担 `/h5` 用户端入口
- 下载页可单独作为轻量静态页面，或在用户 H5 工程中以独立路由页面构建后部署到 `/app`

无论实施细节如何，最终必须满足：

- `/h5` 是用户 H5
- `/app` 是下载页
- 两者在用户视角上是两个不同入口

## 文案要求

### `/h5`

- 标题：`欢迎使用柬聊`
- 副文案：`网页端入口`

### `/app`

- 标题：`柬聊下载`
- Android 主按钮：`下载安装 Android 版`
- iOS 标题：`iPhone / iPad`
- iOS 说明：`当前正在申请签名证书，证书就绪后将开放下载安装`

文案以清晰直接为主，不做营销化描述。

## 异常处理

### `/h5`

- 如果用户未登录，始终落到默认注册态
- 如果登录失败，保留当前认证页并显示错误

### `/app`

- 如果 Android 安装包地址不存在或不可访问：
  - 页面应明确提示“安装包暂不可用，请稍后重试”
  - 不应让下载按钮跳到无意义空白页
- iOS 区块不涉及真实下载，因此不需要处理安装失败场景

## 测试与验收

### 路由验收

- `http://45.202.0.14/` 仍可进入后台
- `http://45.202.0.14/h5` 可进入用户 H5
- `http://45.202.0.14/app` 可进入下载页

### `/h5` 验收

- 未登录默认展示注册态
- 可切换到登录态
- 已登录可进入用户主界面壳

### `/app` 验收

- 页面可公网访问
- Android 区块有明确下载按钮
- Android 下载按钮能触发真实下载
- iOS 区块仅展示说明，不提供下载动作

### 不回归验收

- 后台根路径不受影响
- `/api`、`/socket.io`、`/uploads` 不受影响

## 实施顺序建议

1. 完成 `/h5` 的用户入口改造，并保持未登录默认注册
2. 完成 `/app` 下载页页面
3. 准备 Android APK 的公网下载路径
4. 调整 Nginx 路由分流
5. 做公网回归：
   - `/`
   - `/h5`
   - `/app`
   - Android 下载

## 风险与注意点

- 根路径当前服务后台，改路由时必须避免覆盖 `/`
- `/app` 的 Android 下载按钮依赖真实 APK 路径，实施前必须确定文件落点
- 如果将下载页放入同一前端工程构建，需要确保部署时路径与资源引用正确
- iOS 当前只展示说明，页面里不能误导用户以为已经支持安装

## 结论

本次设计确认使用服务器 IP 的两个临时公网入口：

- `http://45.202.0.14/h5` 作为用户 H5 入口
- `http://45.202.0.14/app` 作为 Android / iOS 下载页

其中：

- H5 入口继续承担用户网页端访问
- 下载页承担 Android 真下载与 iOS 说明展示
- 根路径 `/` 保持后台用途不变

这套方案最适合当前阶段的临时公网演示与分发，也为后续接入 iOS 正式安装能力保留了稳定入口。
