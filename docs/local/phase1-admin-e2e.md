# 阶段 1 后台联调清单

## 统一登录约定

- 统一管理后台通过请求头注入管理员身份：`x-admin-role`、`x-admin-id`
- 后台需要显式录入 `API Base URL`
- 本地主线默认值：`/api`
- 直连后端时使用同一入口，例如：`http://127.0.0.1:3001/api`

## 最小操作流

1. 在统一管理后台登录页输入管理员角色、管理员 ID、API Base URL
2. 先验证健康检查通过，再进入后台
3. `GET /api/admin/users`
4. `POST /api/admin/users/:id/ban`
5. `GET /api/admin/reports`
6. `POST /api/admin/announcements`
7. `GET /api/admin/audit-actions`

## 建议联调顺序

1. 启动阶段 1 后端与初始化数据
2. 进入统一管理后台并完成一次完整管理流
3. 核对用户列表、封禁结果、举报列表、公告创建、审计动作是否一致

## 品牌配置演示补充流程

1. 打开统一管理后台首页，确认暗色仪表盘布局正常展示。
2. 进入“品牌配置”页，先修改移动端项目名称、项目 LOGO、底部背景主题位。
3. 打开 `/h5`，确认 H5 登录页同步展示移动端品牌变化。
4. 返回“品牌配置”页，修改 PC 端项目名称、项目 LOGO、底部背景主题位。
5. 打开 `/`，确认 PC 网页端登录页同步展示 PC 品牌变化。
6. 运行 `pnpm --filter @jianliao/admin-desktop dist:win`，确认产出 Windows `exe` 安装包。

## 70% 真实联调复盘核对项

### 管理后台

- 管理后台是否使用统一管理员身份与统一 API Base URL 完成联调
- 健康检查失败时，后台是否能给出明确提示并阻止继续操作
- 用户列表、封禁、举报、公告、审计动作是否与服务端数据保持一致
- 管理动作执行后，是否能在服务端日志或数据库中定位到对应记录

### 与移动端联动核对

- 后台查看到的用户状态是否与 iOS / Android 当前联调账号一致
- 移动端触发的问题（例如上传失败、消息未送达、回执重复）是否能通过后台与日志交叉定位
- 后台处理完封禁 / 公告后，是否记录了影响范围与恢复动作

## 复盘输出要求

1. 管理后台至少保留一次完整操作流的成功记录。
2. 若任一步骤失败，记录请求入口、管理员身份、失败接口、响应结果与日志时间点。
3. 把后台侧结论同步写入 `docs/local/phase1-real-e2e-review.md` 的“管理后台”章节。
