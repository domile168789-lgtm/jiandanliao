# 柬聊 iOS（SwiftUI）联调说明

## 默认入口

- API：`http://127.0.0.1/api`
- WS：`http://127.0.0.1`

## 当前入口能力

- 登录 / 注册
- 消息 Tab：会话列表、单聊、文本发送、图片发送、READ 回执
- 通讯录 Tab：快速发起单聊、进入最近联系人会话、跳转系统通知
- 发现 Tab：系统通知、钱包、收益、代理四个运营入口
- 我的 Tab：账号摘要、安全状态、通知计数、退出登录
- 安全页：查看设备 ID、API / WS 地址、账号限制状态，并可在本地模拟安全态

## 联调顺序

1. 在仓库根目录启动本地主线依赖服务
2. 打开登录页的“服务地址设置”
3. 确认 API / WS 地址与本地主线一致
4. 完成登录，确认四个 Tab 与系统通知 / 钱包 / 收益 / 代理 / 安全页可进入
5. 回到消息 / 通讯录，完成建单聊、发文本、发图片、写 READ 回执

## 本地主线建议命令

```bash
cd /workspace/jianliao-platform
docker compose -f infra/compose/docker-compose.yml up -d
```

## 70% 真实联调动作

1. iOS 与 Android 使用真实账号连接同一环境，并进入同一单聊。
2. 先完成双向文本消息联调，再完成双向图片联调。
3. 对文本与图片都执行 `READ` 回执，确认列表状态与详情状态都更新。
4. 对照 Android 端、服务端日志与后台数据，确认消息、上传、回执三条链路连续可用。
5. 若出现失败，记录失败步骤、会话 ID、接口返回、Socket 事件与临时恢复动作。

## 联调时的最小核对项

- API：`http://127.0.0.1/api`
- WS：`http://127.0.0.1`
- 是否能稳定登录并保持会话
- 是否能看到四个 Tab 与新增入口页
- 是否能收到 Android 发来的文本与图片
- 是否能把自己的 `READ` 回执回写成功

## 复盘文档

- 所有真实联调问题统一记录到 `docs/local/phase1-real-e2e-review.md`
